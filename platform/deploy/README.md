# Deploying the pilot (INF-04)

One server runs three containers from one image:

| Container | What it does | Holds the database root password? |
|---|---|---|
| `web` | Apache with OpenEMR and the dashboard | No |
| `worker` | Dashboard worker: creates and manages practices | Fetches it at start from Secrets Manager (server IAM role); never written to disk or to the image |
| `caddy` | Front door on port 80 (HTTPS comes with INF-05) | No |

Practice settings and documents live in the `sites` volume, the dashboard's own config in `dashvar`.

## First deploy (on the server, in this folder)

```
sudo ./deploy.sh init <db-endpoint> <db-secret-arn>
sudo ./deploy.sh build          # about 20 to 25 minutes, run it in the background
sudo ./deploy.sh setup          # creates the oe_platform database, its user and tables
sudo ./deploy.sh operator you@company.com "Your Name" owner    # prints a password once
sudo ./deploy.sh up
```

Open `http://admin.<server-ip-with-dashes>.sslip.io/login` (for example `admin.13-51-2-3.sslip.io`).

## What is deliberately not here yet

- HTTPS (INF-05) and the platform domain.
- File permissions are not hardened to read-only: the code tree belongs to the web user. Tighten in SEC-01.
- `sql_upgrade.php`, `acl_upgrade.php` and the other setup scripts are kept out of the web root, in
  `/opt/openemr-setup/` inside the image. The upgrade tool must copy `sql_upgrade.php` and `acl_upgrade.php`
  next to the code for one run and delete them afterwards (TEN-05).
- CCDA service is not installed (not used in Phase 1).
- The image is built on the server. Registry and CI come with INF-08.

## Secrets

Nothing secret is in git or in the image. `.env` holds only the database endpoint and the secret's name.
The dashboard's own database password is generated by `setup` and stored in the `dashvar` volume.
